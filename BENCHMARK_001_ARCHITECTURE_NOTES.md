- The offline desktop client supports accounts, budgets, reports, schedules, file import/export, and local work. Its `No server` mode does not provide browser/PWA access, cross-device sync, or the server-backed API. See [Actual installation options](https://actualbudget.org/docs/install/).
- With a configured server, Actual keeps a local working copy and syncs it to the selected server; its official documentation describes offline operation and multi-device use. End-to-end encryption is optional, has a separate password, and has a password-loss recovery cost. The server administrator can access sync tokens, and local device data is not encrypted by Actual itself. See [syncing across devices](https://actualbudget.org/docs/getting-started/sync/).
- The server-backed UI proof uses the owner-authenticated local session. A separate Chrome Incognito client connected to the same `My Finances` budget and displayed the same six synthetic account balances. A November Food target changed from `$0` to `$600` in Client A; Client B initially showed the old value, then after reopening showed `$600`, the matching `$43,350` To Budget total, and `Server online`. This is observed eventual online convergence after reopening, with a stale first view; it does not establish offline edits or conflict behavior. See `SYNC_ARCH_001_ACTUAL_CLIENT_CHECKPOINT.md`.
- Actual's official API is a Node package, not a REST service. With no `serverURL`, it makes no network connections and can use locally cached files; `runImport` can create a new local budget. Remote-server access requires its password. The documented browser build is experimental and requires cross-origin isolation. This gives a supported offline data-setup/export path, but does not replace UI interaction evidence for the 22 workflow scores. See [Using the API](https://actualbudget.org/docs/api/) and the [API reference](https://actualbudget.org/docs/api/reference/).
- Actual's user directory and per-budget user access require an OpenID Provider. This adds identity-provider setup and ongoing operations if separate household identities are required. See [Managing multi-user support](https://actualbudget.org/docs/config/multi-user/).

## Decision limits

This evidence supports treating Actual's server-backed client as the serious cloud/offline baseline for #56, subject to a real second-client test. It does not establish household usability, conflict handling, replay behavior, interrupted-sync recovery, or spreadsheet exit quality. The interactive import requires category pre-creation for full category fidelity, so category setup effort must be included in the matched score. It does not justify building Gringotts sync. Final architecture/product scoring remains dependent on completing #54's matched 22-job execution.
